## What changed

1. Registered-only saving and account-scoped caches; stale loads cannot overwrite a newer save. A pending catalog Save or Create invitation action survives the existing same-tab sign-in flow and cancels when authentication is dismissed. Failed saving keeps the current result available.
2. Main-place private saving is separate from invitation publishing. Catalog invitations now use the same protected, revocable service, with server catalog/schedule/budget revalidation; demonstrations cannot create real invitations. Existing embedded recipe URLs remain readable, but their already-distributed payloads cannot be retroactively revoked. Merely rendering/accepting the result performs only a private status lookup for signed-in users. Save/Create intent can resume after the existing guest-to-account transfer. Native, WhatsApp and copy-link controls remain available once the link is ready.
3. New public invitation documents receive a safe, category-based preview instead of private AI-written text. Legacy public records are sanitized on read; personalized stories remain in the private plan/history. A regression fixture deliberately inserts sensitive-looking AI prose and verifies it is absent from both the new public document and public responses.
4. Creators can revoke in the accepted-date screen or history using the existing shadcn AlertDialog. Transactions derive ownership from the verified token. Public access stops while private history remains. Recreating an invitation rotates its opaque token.
5. Explicit timezone throughout schedule persistence and public timing. Past days/times fail validation without modifying the chosen inputs. Calendar and chat use the same venue-local day as the server.
6. Required access/dietary facts fail closed when unavailable; empty results explain the source-data limitation. Existing budgets, source records and AI narrative separation remain intact.
7. Visible reveal skip action, preserved red theme/animations, inert covered controls and sanitized server error correlation IDs.
8. One-hour expiry for new planner/active-recipe snapshots, older-version cleanup and Clear answers in the existing exit dialog. Legacy untimestamped drafts migrate on their next save because their original age cannot be inferred.
9. Sign-in UI no longer switches to the account-success view before guest transfer completes. Normal sign-in retries keep the transfer token in memory, never in persistent browser storage.
10. Shared generation leases, stable retry keys, polling and deadlines prevent repeated AI execution for the same logical request. Completed catalog results are recalculated and Maps facts fetched again before replay. Aborted/stale owners cannot complete a newer lease.
11. Extend the existing lab with source-backed disable/re-enable controls, report handling and private funnel counts. Ordinary accounts cannot operate them. Structured customer reports are deduplicated and cannot contain free text.
12. Add rejection reasons and real search changes, propagate exclusions to refinement/swap, and offer one swap candidate. Add past-schedule checks to customization, swap and chat.
13. Minimize browser drafts, use references for new Maps recovery, keep generated private context for one hour, and preserve ephemeral expiry through account merge. Explicit old-device imports revalidate first. Update the short privacy notice to describe actual engineering behavior; it is not a completed legal review.
14. Fix existing-email one-use-code consumption, keep interrupted transfer context in memory, clean invalid/expired link parameters so a new link can be requested, and resume new-tab catalog Save/Share intents.
15. An isolated `npm run dev:demo` entry point clears cloud/AI/Maps credentials in the child process and connects only to local demo Firebase emulators.

No dependencies, provider replacements or security-rule changes were added. New protected routes and additive Firestore indexes/expiry policies are listed below; none has been deployed. A local-only development command was added. No production records, invitations, payments, deployment aliases or billing settings changed.
